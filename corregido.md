## Un detalle pendiente: eliminar la rama de trabajo

La rama `editar-readme` sigue existiendo. El recorrido publicado incluye
eliminarla después de fusionar la PR.

Puedes hacerlo con **Delete branch** en la PR ya fusionada, o desde la lista de
ramas del repositorio. Borrar esa rama no borra la PR ni elimina de `main` el
cambio que ya has fusionado. Es una buena ocasión para distinguir el nombre
de una rama del historial que has integrado. Es algo importante para aprender,
borrar una rama no implica borrar el código porque, si la has integrado, ya el
historial de la rama principal lo tiene incluido. 

No necesitas repetir el ejercicio, crear otra PR ni volver a modificar el README
para completar este paso.

## Orientaciones para el trabajo posterior

El mensaje «Esto es una prueba» identifica poco el cambio. En futuros commits y
PR, intenta describir qué has hecho; por ejemplo, «Añade una presentación al
README». Tu descripción de la PR ya aporta esa información. En este caso has
modificado texto Markdown, no código de un programa.

Quédate con la diferencia entre **commit**, **rama** y **pull request**: el
commit registra un cambio; la rama permite mantener una línea de trabajo; y la
PR propone revisar e integrar cambios. Crear un commit no fusiona una rama, y
cerrar una PR no siempre significa fusionarla: en tu caso sí consta la fusión.
